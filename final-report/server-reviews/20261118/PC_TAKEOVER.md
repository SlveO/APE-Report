# APE 项目 PC 端接管提示词

从现在起，请在 PC 端统筹 APE 项目的规划、实施、审核、证据维护和结题提交。已获授权的任务按依赖推进，完成复核并记录裁决后直接交付。后续审核在 PC 端完成，结果记录在 GitHub，交付无需回传服务器复核。

## 同步与接管

1. 同步 GitHub 仓库 `SlveO/APE-Report` 的 `analysis/main80-pc-results` 分支。先看当前分支和工作树，保护本地变更。报告、分析、审核原件和后续正式交接均使用这个仓库与分支。推送后独立核对远端分支提交，并在任务卡记录交付路径、完整提交 ID 和核验结果。
2. 先读服务器最终裁决、结题正文、统一结果表及生成脚本。复核提交 `feb6828` 后，正文和附表均为 `ACCEPTED`，第 25–26 行的来源勘误已关闭。按需要核对 PC 统计和 FOLLOWUP2604 输入包。[服务器终审索引](README.md) · [勘误复核原件](recheck-feb6828/PLANNER_REVIEW.md) · [结题正文](../../结题报告.md) · [统一结果表](../../统一结果表.csv) · [生成器](../../build_unified_results.py) · [PC 统计](../../../pc-analysis-followup-output/README.md) · [FOLLOWUP2604 输入包](../../../followup2604-20261117/FOLLOWUP2604_ACCEPTED.zip)
3. 保留报告初稿、历次审核原件、已产出的答案和失败记录。根据清单、样本 ID、数量与必要的逐项内容比较核对证据。输入包按包内路径映射使用，服务器绝对路径是当时的归档定位。CSV 如需维护，修改生成逻辑后重生并逐项核对。
